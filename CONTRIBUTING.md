# Contributing to STC-DT

STC-DT welcomes contributions that improve ecosystem documentation, coordination, governance, interoperability planning, and contributor practices.

The umbrella currently focuses on ecosystem documentation, coordination, governance, and interoperability planning. Do not copy component source code into it or add component repositories as Git submodules.

## Ways to contribute

Contributions may:

- correct or clarify documentation;
- confirm component descriptions, links, contributors, inputs, and outputs;
- propose interoperability requirements or shared terminology;
- improve governance, security, or contributor guidance; or
- identify ecosystem roadmap gaps and dependencies.

Changes to a component implementation belong in that component's repository.

## Contribution process

1. Confirm that the proposed change belongs in the STC-DT umbrella.
2. Open an issue when a change requires cross-component discussion or agreement.
3. Submit a focused pull request explaining its purpose and evidence.
4. Label behavior as current, proposed, planned, experimental, or pending confirmation.
5. Cite an authoritative source for claims about a component.
6. Address review comments from the affected contributors.

## Documentation standards

Contributions must not:

- present an unimplemented integration, interface, API, schema, or capability as operational;
- invent publications, contributors, affiliations, or repository links;
- present planned work as current functionality; or
- include third-party material without appropriate permission and attribution.

Use **Pending contributor confirmation** when required information is unavailable.

## Responsibilities

The umbrella repository records ecosystem-level documentation and coordination. Each component repository remains responsible for its implementation, component-specific issues, releases, dependencies, and security guidance.

Cross-component proposals should record their status, unresolved questions, affected components, and evidence of agreement. A proposal is not an adopted ecosystem standard until that adoption is documented.

All participants must follow the [Code of Conduct](CODE_OF_CONDUCT.md) and handle potential security concerns according to [SECURITY.md](SECURITY.md).
