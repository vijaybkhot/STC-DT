# Security Policy

## Repository scope

STC-DT is currently a documentation and coordination repository. It does not contain, deploy, or integrate the source code of the three component projects.

Security concerns involving a component implementation should follow the security policy published by that component repository. The umbrella does not replace component maintainers' response responsibilities.

## Reporting an umbrella concern

Formal ecosystem security contacts and coordinated-response arrangements are still being established.

Do not include vulnerability details, credentials, personal data, or confidential research information in a public issue. Non-sensitive documentation corrections may use the normal contribution process. Until a private ecosystem channel is published, a reporter may open a non-sensitive issue requesting private reporting instructions without disclosing the security concern.

## Current limitations

No umbrella-level response time, disclosure timeline, severity model, or cross-repository coordination process has yet been adopted. These omissions describe the current state of ecosystem governance, not the maturity of any individual component's security process.

## Planned ecosystem coordination

Future security work may address:

- ownership and routing of cross-component reports;
- coordinated disclosure across independently maintained repositories;
- dependency and provenance documentation;
- authentication, authorization, privacy, and data-governance boundaries; and
- security review of any adopted shared interfaces or protocols.

These are planned practices and are not currently implemented across STC-DT.
